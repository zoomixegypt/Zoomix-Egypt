# ZOOMIX Main Site — Visual & Interaction Style Guide

> تحليل عملي للهوية البصرية والتفاعلية للموقع الأساسي، مبني على مراجعة الواجهة الفعلية على الديسكتوب والموبايل، ومراجعة مكونات React وقواعد CSS الحالية.

## 1. ملخص الهوية

هوية Zoomix هي **Editorial Creative System** بطابع تقني وجريء. الشكل يجمع بين:

- مساحات سوداء مسرحية تعرض الرسالة والأعمال بقوة.
- مساحات ورقية هادئة تنظّم الشرح والمراحل.
- أخضر فسفوري يستخدم كإشارة قرار وحركة، وليس كلون زخرفي عشوائي.
- عناوين ضخمة جدًا مقابل تفاصيل صغيرة ومنظمة بخط Mono.
- شبكة هندسية، خطوط اتصال، أرقام وتسميات تجعل التجربة تبدو كنظام إبداعي متكامل.
- حركة مقصودة تشرح الانتقال والتتابع بدل إضافة مؤثرات بلا وظيفة.

الانطباع المطلوب: **جريء، معاصر، واضح، إبداعي، دقيق، وغير تقليدي**.

## 2. المبادئ الأساسية

### 2.1 التباين هو أساس التصميم

الصفحات تتحرك بين عالمين رئيسيين:

1. **Dark Stage:** خلفية سوداء، نص أبيض، وأخضر فسفوري للحركة والقرار.
2. **Paper Workspace:** خلفية off-white، نص أسود، وحدود خفيفة لتنظيم المعلومات.

لا يُفضّل إنشاء درجات رمادية كثيرة أو إضافة ألوان جديدة؛ قوة الهوية تأتي من محدودية الألوان وشدة التباين.

### 2.2 الأخضر يعني شيئًا

الأخضر الفسفوري يظهر في:

- الدعوة الأساسية للفعل.
- الكلمة المحورية في العنوان.
- الحالة النشطة أو الاختيار الحالي.
- النقاط والخطوط التي تقود العين.
- الأرقام والتسميات المهمة.
- Hover وFocus للأفعال القابلة للنقر.

لا يُستخدم كخلفية لمساحات كبيرة إلا في شرائط الحركة أو لحظة بصرية مقصودة.

### 2.3 الكبير يشرح الفكرة، والصغير يشرح النظام

- العنوان الكبير يقدّم النتيجة أو الوعد.
- النص المتوسط يشرح القيمة بلغة مباشرة.
- خط Mono الصغير يقدّم التصنيف، الرقم، الحالة، أو المرحلة.

هذه الطبقات الثلاث يجب أن تبقى واضحة في أي صفحة جديدة.

### 2.4 الحواف الحادة هي الوضع الافتراضي

الهوية تعتمد على المستطيلات، الحدود، الخطوط والزوايا الواضحة. الاستدارة الكاملة محجوزة للعناصر التالية:

- أزرار أو عقد صغيرة دائرية.
- مؤشر حالة أو رقم.
- التنقل العائم أو غلاف CTA محدد.
- أشكال مدارية زخرفية.

البطاقات الأساسية لا تتحول إلى واجهة SaaS ممتلئة بزوايا دائرية.

## 3. Design Tokens الحالية

```css
:root {
  --zoomix-black: #0a0a0a;
  --zoomix-lime: #bbff00;
  --zoomix-white: #ffffff;
  --zoomix-off-white: #f5f4ef;
  --zoomix-gray: #a5a5a5;
  --zoomix-border: rgba(165, 165, 165, 0.28);
  --zoomix-radius: 0;
  --zoomix-space-section: clamp(4.5rem, 8vw, 8rem);
  --zoomix-ease: cubic-bezier(0.16, 1, 0.3, 1);

  --font-sans: "Space Grotesk", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  --font-display: "Space Grotesk", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
  --font-mono: "JetBrains Mono", Menlo, Monaco, Consolas, monospace;
  --font-arabic: "Cairo", Tahoma, Arial, sans-serif;
}
```

### أدوار الألوان

| اللون | الدور |
|---|---|
| `#0A0A0A` | المسرح الداكن، الخلفيات الرئيسية، النص على الأخضر |
| `#BBFF00` | القرار، الحركة، الحالة النشطة، الكلمات المحورية |
| `#F5F4EF` | المساحات التفسيرية والنماذج والمحتوى الطويل |
| `#FFFFFF` | النص الأساسي فوق الأسود والبطاقات الفاتحة |
| `#A5A5A5` | المعلومات الثانوية فقط |
| شفافية 10–28% | الحدود والتقسيم بدون ضوضاء بصرية |

### نسب استخدام مقترحة

- الأسود وOff-white: حوالي 80–90% من المشهد.
- الأبيض والرماديات: للنصوص والحدود.
- الأخضر: حوالي 5–10%، ويظل اللون الأعلى أهمية بصريًا.

## 4. Typography

### العربية

- الخط الأساسي: `Cairo`.
- العناوين: وزن 800–900، وتباعد طبيعي أو سالب بسيط جدًا.
- النص: وزن عادي أو متوسط، مع `line-height` واسع نسبيًا بين `1.7–1.9`.
- لا يتم إجبار العربية على Uppercase أو letter-spacing لاتيني.

### الإنجليزية

- العناوين والعرض: `Space Grotesk`.
- بيانات النظام والتصنيفات: `JetBrains Mono`.
- العناوين الكبيرة تستخدم تباعدًا سالبًا قويًا يصل إلى `-0.055em` أو `-0.06em`.

### سلم الأحجام

- Hero: `clamp(2.75rem, 12vw, 8.7rem)` على الموبايل ثم `clamp(3.6rem, 9vw, 8.7rem)` للشاشات الأكبر.
- عناوين الأقسام: غالبًا `2.25rem–3.75rem` حسب الشاشة.
- مقدمة القسم: `1.25rem–1.5rem` مع سطر مريح.
- النص الأساسي: `0.875rem–1.125rem`.
- Labels / Kicker: `0.56rem–0.7rem` بخط Mono وتباعد `0.14em–0.22em`.

### قاعدة كتابة العنوان

العنوان قصير ونتيجته مباشرة، مع كلمة واحدة فقط غالبًا باللون الأخضر:

```text
خلي مشروعك
يظهر
بالشكل اللي يستحقه.
```

يُفضّل كسر الأسطر تحريريًا بدل ترك المتصفح يقررها بالكامل.

## 5. Grid, Layout & Spacing

- أقصى عرض للمحتوى بين `1380px` و`1400px`.
- الحواف الأفقية: `24px` على الموبايل، و`48px` على الديسكتوب.
- مسافة القسم: `clamp(4.5rem, 8vw, 8rem)`.
- Hero يشغل `100svh` ويعمل كمشهد كامل، لا كبانر قصير.
- التقسيمات الأساسية تستخدم Grid غير متماثل مثل `1.2fr / 0.8fr` أو `0.9fr / 1.1fr`.
- الحدود الرفيعة تفصل الأفكار بدل الاعتماد على Card Shadows.
- الفراغ جزء من الهوية؛ لا يجب ضغط كل المحتوى داخل أول شاشة.

### الشبكة الزخرفية

خلفية الـHero تستخدم شبكة `56px × 56px` بخطوط بيضاء منخفضة الشفافية، ومعها دوائر مدارية ضخمة. الغرض هو تقديم إحساس «نظام/استوديو/مسار»، وليس ملء الفراغ.

## 6. بنية الصفحة الرئيسية

الترتيب الحالي يحكي رحلة متصاعدة:

1. **Navigation:** هوية + تنقل + قرار البدء.
2. **Hero:** وعد قوي، تفسير مختصر، ثم CTA أساسي وثانوي.
3. **Marquee:** عرض نطاق الخدمات بإيقاع بصري مرتفع.
4. **Services / Why Zoomix:** الانتقال من الوعد إلى منطق النظام.
5. **Route Finder Entry:** مساعدة المستخدم على تحديد الخطوة المناسبة.
6. **Transition Signal:** فصل تحريري قبل عرض الأعمال.
7. **Project Gallery:** إثبات بصري داكن وغامر.
8. **Selected Work References:** دعم الأعمال بمعلومات مختصرة.
9. **Packages:** تحويل الاهتمام إلى اختيار تجاري واضح.
10. **Process / FAQ:** تقليل القلق وتوضيح طريقة العمل.
11. **Project Brief:** تحويل القرار إلى طلب قابل للتنفيذ.
12. **Footer:** إغلاق بصري ومعلومات الاتصال.

أي إضافة جديدة يجب أن تجد مكانها داخل هذه القصة، لا أن تُضاف كقسم مستقل بلا دور.

## 7. المكونات البصرية الأساسية

### 7.1 الأزرار

- ارتفاع أدنى: `48px` تقريبًا.
- وزن النص: 700.
- الزوايا حادة غالبًا.
- CTA أساسي: خلفية أخضر + نص أسود.
- CTA ثانوي على الداكن: خلفية سوداء/شفافة + حد أبيض.
- Hover: ارتفاع `-2px` وتبديل واضح للون.
- الانتقال: `220ms` باستخدام `--zoomix-ease`.

### 7.2 Labels وKickers

- Mono، صغيرة، Uppercase في الإنجليزية.
- إما أخضر على أسود أو أسود على أخضر.
- تُستخدم مرة واحدة لافتتاح كل مجموعة، وليست فوق كل فقرة.

### 7.3 خطوط الاتصال

خط أخضر بسمك `2px` مع عقدة دائرية في النهاية. يُستخدم لربط المراحل أو توجيه العين بين عناصر مترابطة.

### 7.4 بطاقات الخدمات

- لا تعتمد على خلفية بطاقة واضحة.
- تبدأ بخط علوي خفيف.
- دائرة رقم خضراء.
- عنوان ثقيل، وصف، وسهم بسيط.
- تظهر تدريجيًا بتأخير متتابع قصير.

### 7.5 بطاقات المشروعات

- صورة كبيرة هي البطل.
- طبقة سوداء/Gradient لحماية القراءة.
- التصنيف والحالة بأخضر أو Mono.
- العنوان كبير وقريب من حافة البطاقة.
- حركة Hover محدودة: حد أخضر، ظل خفيف، أو Scale بسيط.
- الديسكتوب يستخدم تجربة أفقية Pinned، والموبايل يستخدم Native horizontal snap.

### 7.6 الباقات والنماذج

- خلفية داكنة للباقات مع حدود بيضاء ضعيفة.
- الباقة المميزة تحصل على حد أخضر وخلفية خضراء شفافة فقط.
- تفاصيل الباقة تبقى ظاهرة؛ لا يتم إخفاؤها لصالح شكل مختصر مبهم.
- النماذج تظهر كلوحة ورقية فاتحة فوق محيط داكن، مع خط أخضر علوي.

### 7.7 التنقل

- ثابت أعلى الصفحة.
- يتغير تلقائيًا حسب القسم الداكن أو الفاتح.
- عند التمرير يستخدم خلفية شفافة مع Blur `12px`.
- الديسكتوب: شعار، Capsule تنقل، زر لغة، وCTA.
- الموبايل: زر قائمة دائري أعلى الشاشة، مع Bottom Bar للقرارات الأساسية.

## 8. Motion Language

الحركة في Zoomix تعتمد على أربعة أنماط:

1. **Reveal:** ظهور مع `opacity + translate` عند دخول القسم.
2. **Draw:** رسم خطوط الاتصال تدريجيًا.
3. **Flow:** Marquee مستمر بسرعات هادئة `28–32s`.
4. **Feedback:** رفع الزر، نبضة نقطة، Pop لعلامة النجاح.

### قواعد الحركة

- Ease الأساسي: `cubic-bezier(0.16, 1, 0.3, 1)`.
- حركة UI قصيرة: `220–360ms`.
- Reveals: حوالي `550–900ms`.
- التأخير المتتابع بين العناصر: `60–100ms`.
- الحركة الدائمة بطيئة ولا تنافس القراءة.
- يجب احترام `prefers-reduced-motion`.
- Noise Overlay يظهر فقط مع مؤشر دقيق وعندما لا يكون Reduce Motion مفعّلًا.

## 9. Responsive Style

### الموبايل

- يحتفظ بالـHero الداكن والشبكة والعنوان الكبير؛ لا يتحول إلى نسخة صغيرة تقليدية.
- يبدأ العنوان مبكرًا بعد مساحة آمنة للتنقل.
- النصوص أقل، لكن الوعد الرئيسي يظل كاملًا.
- Bottom Bar ثابت يقدّم أربع وجهات عملية بدل تكرار تنقل الديسكتوب.
- البطاقات الأفقية تستخدم Swipe وSnap أصليين.
- الأزرار التفاعلية لا تقل عن `44px`.
- المسافات الجانبية الأساسية `24px`.

### الديسكتوب

- يسمح بالمساحات المسرحية والعناوين الضخمة.
- يعتمد على Grid غير متماثل وSticky/Pinned experiences.
- يعرض خط الاتصال والشعار الثانوي والعناصر الزخرفية الكاملة.
- أقصى عرض ثابت يمنع تشتت المحتوى على الشاشات الكبيرة جدًا.

## 10. الصور والمعالجة البصرية

- الصور تميل إلى طابع تحريري/سينمائي، وليس صور Stock لامعة.
- تُستخدم الظلال وGradients السوداء لحماية النص.
- لا يُضاف الأخضر كفلتر على الصور؛ يظل لون Interface فوق الصورة.
- الصور داخل المعرض كبيرة وقليلة، وليست Grid من Thumbnail صغيرة.
- Noise خفيف جدًا (`opacity: 0.03`) مع `mix-blend-overlay` لإضافة ملمس.

## 11. نبرة النص داخل الواجهة

- الجملة قصيرة، مصرية، مباشرة، ومرتبطة بالنتيجة.
- لا نستخدم لغة وكالات عامة مثل «نحوّل أفكارك إلى واقع» بدون معنى محدد.
- العنوان يقدم التحول، والوصف يوضح الوسيلة.
- CTA فعل واضح: «حدد خطوتك»، «شوف أعمالنا»، «ابدأ مشروعك».
- الإنجليزية تستخدم صياغات قصيرة بنبرة Editorial: `BUILD THE BRAND`, `SHOW THE WORK`, `LAUNCH WITH CLARITY`.

## 12. ما يجب الحفاظ عليه

- لوحة الألوان المحدودة.
- العنوان الضخم مع كلمة Accent واحدة.
- التبادل بين الأقسام الداكنة والفاتحة.
- Mono labels والأرقام.
- الحدود الحادة والخطوط التنظيمية.
- أخضر مرتبط بالقرار والحالة.
- الحركة الوظيفية لا الاستعراضية.
- اختلاف مدروس بين تجربة الديسكتوب والموبايل.

## 13. ما يجب تجنبه

- استخدام ألوان Branding إضافية بلا ضرورة.
- بطاقات كثيرة بزوايا مستديرة وظلال SaaS تقليدية.
- وضع الأخضر في كل عنوان أو كل أيقونة حتى يفقد أهميته.
- Gradients ملونة أو Glassmorphism ثقيل.
- نصوص طويلة داخل الـHero.
- حركات Scale قوية أو Parallax يضعف القراءة.
- إخفاء تفاصيل الباقات أو الأسعار المهمة.
- نسخ تخطيط الديسكتوب حرفيًا على الموبايل.
- استخدام خط Mono للنصوص العربية الطويلة.
- إضافة أقسام لا تخدم رحلة: وعد ← إثبات ← اختيار ← طلب.

## 14. Checklist لأي شاشة جديدة

قبل اعتماد شاشة أو مكوّن جديد:

- [ ] هل الخلفية تنتمي بوضوح إلى Dark Stage أو Paper Workspace؟
- [ ] هل للأخضر وظيفة قرار أو حالة واضحة؟
- [ ] هل يوجد ترتيب بصري واضح: Kicker ثم عنوان ثم شرح ثم فعل؟
- [ ] هل العنوان قصير وجريء وتحريري؟
- [ ] هل الحواف والحدود متوافقة مع الطابع الحاد؟
- [ ] هل المسافات واسعة بما يكفي؟
- [ ] هل الحركة تشرح العلاقة أو تقدم Feedback؟
- [ ] هل الموبايل مصمم كرحلة مستقلة وليس تصغيرًا للديسكتوب؟
- [ ] هل كل العناصر التفاعلية قابلة للاستخدام بالكيبورد واللمس؟
- [ ] هل الشاشة تقود إلى خطوة تالية واضحة؟
